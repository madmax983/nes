**Flattening `apply_cpu_write_side_effect` and `advance_hardware_cycles` in `NesCore` API**
**Learning:** `apply_cpu_write_side_effect` had a sequence of decoupled `if / else` blocks assigning booleans, followed by decoupled `if` blocks for hardware interactions, creating a massive, highly-coupled flow. `advance_hardware_cycles` had deep nesting (`for` > `for` > `if let` > `if`).
**Action:** Replaced `if` cascade with a `match addr` block and mutable booleans for side-effects, making it a single guardable step. Extracted the inner loop of `advance_hardware_cycles` into `tick_ppu_and_mapper` and used `let Some(...) else { return }` for early return in `pump_mapper_chr_fetches`.
