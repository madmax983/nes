**Eliminate Vec<i16> per-frame allocation in audio chunk delivery**
**Learning:** Returning `Vec<T>` from a hot-path function forces heap allocations. The existing `audio_chunk_i16` allocated a `Vec<i16>` every frame only to push it to a queue or drop it. We already had a `fill_audio_chunk_i16` that could write into an existing buffer.
**Action:** Changed the trait and implementation of `AudioSinkControl::append_i16` and `AudioOutput::queue_samples` to take `&[i16]` slices instead of owned `Vec<i16>`. Lifted the `let mut dummy = [0_i16; nes_core::AUDIO_CHUNK_SAMPLES]` buffer out of the conditional path so it can be used for both dropping and queueing, completely eliminating the heap allocation on every single frame loop iteration.
