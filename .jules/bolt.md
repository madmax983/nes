**[Optimizing JSON-RPC string parsing in `nes-mcp`]
**Learning:** Returning borrowed `&str` references directly from `BTreeMap` lookups (using standard lifetimes like `<'a>`) avoids unnecessary string cloning when parsing command arguments. The borrow checker smoothly accepts this as long as the parsed parameters don't outlive the request context, deferring explicit `to_owned()` calls only to the terminal structs that actually require ownership.
**Action:** When extracting values from configuration or parameter maps for immediate consumption by helper functions (e.g. `std::fs::read(path)`), use `&str` instead of calling `.cloned()` or creating intermediate Strings.
