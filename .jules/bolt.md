**[Optimized RTA Events and Configuration Loading]**
**Learning:** `.find_map` closure evaluation creates overhead on a critical hotpath. Pre-constructing objects and avoiding `String` copies via `&str` or by using partial ownership via `.or` instead of `.or_else(|| value.clone())` gives measurable benchmark improvements without borrow checker complexity.
**Action:** Always prefer `for` loop iteration with direct evaluation over closure-based iteration (like `find_map` or `filter_map`) when scanning small vectors on hot paths. In configuration fallbacks, prefer consuming `Option` resolution by value when `Clone` is expensive.
